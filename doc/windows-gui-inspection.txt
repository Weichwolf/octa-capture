Windows GUI inspection under Wine, 2026-10-18
============================================

Result
------
The original 64-bit OCTA-CAPTURE Control Panel starts under Wine and draws
its preamp/compressor interface. It displays "The device could not be found."
The Driver menu and About dialog are accessible. The Direct Mixer view did
not open in this disconnected state. A separate offline model subsequently
exposed the connected views described below. No hardware control or audio streaming
was verified. This is an observation of the unmodified GUI, not a functional
Windows driver running under Linux.

Environment and launch
----------------------
Wine 10.0 (Debian 10.0~repack-6), a separate win64 prefix, and Xvfb with a
1600x1000, 24-bit screen. No changes were made to the device firmware or
its Linux driver binding. Source archive: octa_w1011d_v153DL.zip, version
1.5.3; see drivers-manifest.json for provenance and checksums.

Files were extracted to /tmp/octa-capture-windows-gui. The following commands
reproduce the launch after extraction (choose an unused display number):

  # Start Xvfb in a separate terminal:
  Xvfb :97 -screen 0 1600x1000x24 -nolisten tcp -ac
  # In the application terminal:
  mkdir -m 0700 -p /tmp/octa-capture-wine
  export DISPLAY=:97 WINEARCH=win64 WINEPREFIX=/tmp/octa-capture-wine
  /usr/lib/wine/wine64 wineboot.exe -u
  cd /tmp/octa-capture-windows-gui/Files
  /usr/lib/wine/wine64 RDDP1110.EXE

The RDCP1110.CPL control-panel entry was also launched using control.exe;
it brought the same main interface forward rather than exposing a separate
settings window in this test. No claim is made about additional dialogs
available when the Windows driver recognizes a device.

Observed layout
---------------
The main window measures 978x408 pixels in this Wine configuration, excluding
window-manager decorations. Native Windows font rendering and dimensions
have not been compared.

- A slim Driver menu bar above a metallic header.
- AUTO-SENS button at the top left; OCTA-CAPTURE branding in the header;
  DIRECT MIXER button with a downward arrow at the top right.
- Eight vertical channel strips, grouped into four stereo pairs.
- Preamp controls: SENS rotary knob, +48 phantom power, LO-CUT, PHASE;
  Hi-Z is shown for channels 1 and 2.
- Per-channel compressor section: BYPASS, input/output level meters with
  clip indicators, transfer graph, and GATE, THRESHOLD, GAIN, ATTACK,
  RELEASE, and RATIO rotary controls.
- LINK button for each channel pair; channel numbers at the bottom.
- A centered disconnected-device message overlays part of the controls.

The Driver menu contains Always on top, Show README (disabled in this test),
About Driver & Control Panel..., and Exit (Alt+F4).

The About dialog measures 483x114 pixels. It shows the product name,
Roland copyright, an OK button, an audio-port warning checkbox, and an
ASIO attribution.

Connected views with an offline model
------------------------------------
A private analysis prototype redirects the original executable's device-file,
IOCTL and device-metadata registry imports to an in-memory model. The executable
and its resources are unchanged on disk. Wine audio backends are disabled;
there is no USB forwarding, Windows kernel driver or Linux device control.
This provides a visual reference, not verified Windows hardware behavior.

The GUI probes \\.\Rdwm1110001 through 004 and corresponding Rdwm1110Ex paths.
The model accepts only the first ordinary path and supplies synthetic 48 kHz
metadata, state and notification events. Incomplete IOCTL semantics and the
zeroed device-state model limit behavioral conclusions. The prototype remains
under ignored build/wine-reference/ and is not a supported compatibility bridge.

The connected panel measures 978x429 pixels in the Wine X-window capture,
including the menu and a 21-pixel bottom bar, excluding window-manager decorations.
The bar contains a device button/lamp, SAMPLE RATE selector and CLOCK display.
The Direct Mixer view contains INPUT MIXER A and WAVE OUT MIXER A, ten strips
each, with a master section for output-jack assignment, input/output linking,
reverb type/return and linked master faders. The Device menu exposes Save/Load
settings, Open the Patch Bay, Directly Output the Inputs, Initialize and signal
flow. These observations agree with the previously extracted menus/resources;
the model does not establish correct effects of their commands.

Patch Bay and Reverb also open against the model. Their client areas measure
227x189 and 195x135 pixels, matching dialog resources 178 (151x126 dialog units)
and 188 (130x90). Patch Bay has a top Preset row with Multi-Monitor and Initial
Setting, five output selectors and a bottom Close button. Reverb has a type
selector, compact read-only pre-delay/time spinners and two bottom buttons.

Connected captures are stored under doc/local/windows-gui/ as
direct-mixer-offline-model.png, patchbay-offline-model.png and
reverb-offline-model.png. Only our own HTML/CSS/vector artwork is shipped.
Native Windows font rendering and full visual parity remain unverified.

In the connected offline model, Ctrl+S/Ctrl+O/Ctrl+P open Save/Open/Patch Bay
from the main panel. Auto-Sens and Patch Bay modal dialogs suppress these file
shortcuts; Ctrl+Shift+S does not invoke Save. Accelerator resource 128 confirms
Ctrl-only O/S/P commands 0x8053/0x8054/0x805C (flags 0x0B, no Shift/Alt).
Its additional Space/0x807B entry has no established command behavior yet.

Auto-Sens selection also opens against the offline model (local capture:
auto-sens-selection-offline-model.png, 294x146 client pixels). It has two rows
of four inputs, Select All/Clear All at the right and Start/Cancel below. Empty
selection disables Start. Idle selection is empty again after Cancel/reopen.
Original code qualifies this observation: 0x140019700 copies device-model
activity flags at 0x228..0x244, entering the running state when any is set.
These flags are not part of the bulk bank. 0x14001eec0 alternates the running
indicator with 800 ms visible/200 ms hidden timers. Finish (0x14001d420) and
Cancel (0x14001b600) stop calibration and close the dialog. macOS independently
confirms selection guards and Finish/Cancel behavior. The offline display model
does not prove actual Windows calibration or notification behavior.

Windows driver compatibility checks
-----------------------------------
The vendor INF registers RDWM1110.SYS with ServiceType=1
(SERVICE_KERNEL_DRIVER). Its import table requires ntoskrnl.exe, USBD.SYS,
and portcls.sys, including PcInitializeAdapterDriver, PcNewPort, and
PcRegisterSubdevice. No portcls implementation was found in the installed
Wine 10.0 library directories. This is a concrete blocker to loading the
original Roland driver in the current Wine environment; an installer
completing would not demonstrate a working driver.

RDDP1110.EXE imports CreateFileW and DeviceIoControl. Its discovery paths and
enough of its control interface for the offline display model are traced;
full device-dependent interaction remains incomplete. A working Linux
ALSA driver would not automatically provide the Windows driver interface
expected by the vendor GUI. A dedicated compatibility bridge could be
investigated separately if running the original GUI becomes a goal.

Wine does include USB support; do not generalize these findings into a
claim that Wine cannot access USB devices or run any driver-related code.
Reference for the tested Wine version:
https://github.com/wine-mirror/wine/blob/wine-10.0/dlls/wineusb.sys/wineusb.c
