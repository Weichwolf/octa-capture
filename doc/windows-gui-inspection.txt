Windows GUI inspection under Wine, 2026-10-18
============================================

Result
------
The original 64-bit OCTA-CAPTURE Control Panel starts under Wine and draws
its preamp/compressor interface. It displays "The device could not be found."
The Driver menu and About dialog are accessible. The Direct Mixer view did
not open in this disconnected state. A separate offline model subsequently
exposed the connected views described below. No hardware control or audio streaming
was verified. This is an observation of the unmodified GUI, not a functional
Windows driver running under Linux.

Environment and launch
----------------------
Wine 10.0 (Debian 10.0~repack-6), a separate win64 prefix, and Xvfb with a
1600x1000, 24-bit screen. No changes were made to the device firmware or
its Linux driver binding. Source archive: octa_w1011d_v153DL.zip, version
1.5.3; see drivers-manifest.json for provenance and checksums.

Files were extracted to /tmp/octa-capture-windows-gui. The following commands
reproduce the launch after extraction (choose an unused display number):

  # Start Xvfb in a separate terminal:
  Xvfb :97 -screen 0 1600x1000x24 -nolisten tcp -ac
  # In the application terminal:
  mkdir -m 0700 -p /tmp/octa-capture-wine
  export DISPLAY=:97 WINEARCH=win64 WINEPREFIX=/tmp/octa-capture-wine
  /usr/lib/wine/wine64 wineboot.exe -u
  cd /tmp/octa-capture-windows-gui/Files
  /usr/lib/wine/wine64 RDDP1110.EXE

The RDCP1110.CPL control-panel entry was also launched using control.exe;
it brought the same main interface forward rather than exposing a separate
settings window in this test. No claim is made about additional dialogs
available when the Windows driver recognizes a device.

Observed layout
---------------
The main window measures 978x408 pixels in this Wine configuration, excluding
window-manager decorations. Native Windows font rendering and dimensions
have not been compared.

- A slim Driver menu bar above a metallic header.
- AUTO-SENS button at the top left; OCTA-CAPTURE branding in the header;
  DIRECT MIXER button with a downward arrow at the top right.
- Eight vertical channel strips, grouped into four stereo pairs.
- Preamp controls: SENS rotary knob, +48 phantom power, LO-CUT, PHASE;
  Hi-Z is shown for channels 1 and 2.
- Per-channel compressor section: BYPASS, input/output level meters with
  clip indicators, transfer graph, and GATE, THRESHOLD, GAIN, ATTACK,
  RELEASE, and RATIO rotary controls.
- LINK button for each channel pair; channel numbers at the bottom.
- A centered disconnected-device message overlays part of the controls.

The Driver menu contains Always on top, Show README (disabled in this test),
About Driver & Control Panel..., and Exit (Alt+F4).

The About dialog measures 483x114 pixels. It shows the product name,
Roland copyright, an OK button, an audio-port warning checkbox, and an
ASIO attribution.

Connected views with an offline model
------------------------------------
A private analysis prototype redirects the original executable's device-file,
IOCTL and device-metadata registry imports to an in-memory model. The executable
and its resources are unchanged on disk. Wine audio backends are disabled;
there is no USB forwarding, Windows kernel driver or Linux device control.
This provides a visual reference, not verified Windows hardware behavior.

The GUI probes \\.\Rdwm1110001 through 004 and corresponding Rdwm1110Ex paths.
The model accepts only the first ordinary path and supplies synthetic 48 kHz
metadata, state and notification events. Incomplete IOCTL semantics and the
zeroed device-state model limit behavioral conclusions. The prototype remains
under ignored build/wine-reference/ and is not a supported compatibility bridge.

The connected panel measures 978x429 pixels in the Wine X-window capture,
including the menu and a 21-pixel bottom bar, excluding window-manager decorations.
The bar contains a device button/lamp, SAMPLE RATE selector and CLOCK display.
The Direct Mixer view contains INPUT MIXER A and WAVE OUT MIXER A, ten strips
each, with a master section for output-jack assignment, input/output linking,
reverb type/return and linked master faders. The Device menu exposes Save/Load
settings, Open the Patch Bay, Directly Output the Inputs, Initialize and signal
flow. These observations agree with the previously extracted menus/resources;
the model does not establish correct effects of their commands.

Patch Bay and Reverb also open against the model. Their client areas measure
227x189 and 195x135 pixels, matching dialog resources 178 (151x126 dialog units)
and 188 (130x90). Patch Bay has a top Preset row with Multi-Monitor and Initial
Setting, five output selectors and a bottom Close button. Reverb has a type
selector, compact read-only pre-delay/time spinners and two bottom buttons.

Connected captures are stored under doc/local/windows-gui/ as
direct-mixer-offline-model.png, patchbay-offline-model.png and
reverb-offline-model.png. Only our own HTML/CSS/vector artwork is shipped.
Native Windows font rendering and full visual parity remain unverified.

The read-only layout inspector also captures dialogs owned by the hash-verified
original process. test/data/dialog-geometry.json records 14 Patch Bay, 10 Reverb
and 13 idle Auto-Sens control bounds at 96 DPI, including the runtime-adjusted
edit/up-down rectangles. All three client sizes and these 37 rectangles match
Chromium and native GTK/WebKit. The inspector only observes the visible dialog;
the Wine device-interface model does not establish physical device behavior.

In the connected offline model, Ctrl+S/Ctrl+O/Ctrl+P open Save/Open/Patch Bay
from the main panel. Auto-Sens and Patch Bay modal dialogs suppress these file
shortcuts; Ctrl+Shift+S does not invoke Save. Accelerator resource 128 confirms
Ctrl-only O/S/P commands 0x8053/0x8054/0x805C (flags 0x0B, no Shift/Alt).
The additional unmodified Space/0x807B entry is consumed without an action in
the main frame: base pretranslation (0x14004EF9C) calls TranslateAcceleratorW,
which returns 1, but WM_COMMAND 0x807B returns 0 (unhandled). The same probe
returns 1 for the known Always on top command 0x8056; Ctrl+Space is not
translated. The decoded command maps contain no 0x807B handler. These are
original Windows x64 code and offline Wine observations, not hardware evidence.
The Linux main panel therefore suppresses unmodified Space; popup menus and
modal dialogs retain their own keyboard behavior.

Menu resource 128 uses &Driver and De&vice. The offline model confirms that
Alt+D/V open these menus, F10 focuses Driver without opening a popup, Left/Right
switch open root menus, and I opens Initialize. Its A/M/D/R/P bindings select
All/MIC PRE/DIRECT MIX/REVERB/PATCHBAY. In the Device popup S immediately opens
Save, although both Save and Show the signal flow have S in the resource;
the original MFC menu selects the first match instead of cycling. The Save
chooser was cancelled without writing a file. Captures remain in ignored
build/wine-reference/menu-*.png. These observations do not verify hardware
commands or complete Windows keyboard behavior.

Auto-Sens selection also opens against the offline model (local capture:
auto-sens-selection-offline-model.png, 294x146 client pixels). It has two rows
of four inputs, Select All/Clear All at the right and Start/Cancel below. Empty
selection disables Start. Idle selection is empty again after Cancel/reopen.
Original code qualifies this observation: 0x140019700 copies device-model
activity flags at 0x228..0x244, entering the running state when any is set.
These flags are not part of the bulk bank. 0x14001eec0 alternates the running
indicator with 800 ms visible/200 ms hidden timers. Finish (0x14001d420) and
Cancel (0x14001b600) stop calibration and close the dialog. macOS independently
confirms selection guards and Finish/Cancel behavior. The offline display model
does not prove actual Windows calibration or notification behavior.

Dialog window behavior, 2026-10-19
----------------------------------
The offline model's Patch Bay window has WS_CAPTION and WS_SYSMENU
(observed style 0x94c800cc). A Win32 SetWindowPos displacement of 100/60 pixels
is retained while it is open. SC_CLOSE closes that modal; reopening with Ctrl+P
creates it at its original centered position. The observation is recorded in
ignored build/wine-reference/dialog-window-observations.json. This checks window
creation/system-close behavior against the model, not native Windows rendering,
physical hardware or an original mouse-drag handler.
Six sampled parent-panel pixels outside the modal match the corresponding
uncovered main-view capture exactly; the reference does not dim the owner panel.

Dialog keyboard behavior
------------------------
Resources 100/178/188/266/289 declare default pushbutton ID 1. Their 27 Tab
stops are recorded as numeric IDs in test/data/dialog-keyboard.json; optional
tools/verify-dialog-resources.py checks them against the hash-pinned executable.
Patch Bay cycles Close, Multi-Monitor, Initial Setting and output selectors 1–5.
Reverb cycles Close, Initial Setting and Type; its read-only edit/up-down pairs
have no WS_TABSTOP. About and the port warning put OK/Close before the checkbox.
Auto-Sens orders Start, Cancel, inputs 1–8, Select All and Clear All; disabled
controls are skipped, so empty idle selection initially focuses Cancel.

GetGUIThreadInfo/DM_GETDEFID and actual X11 keys in the offline Wine model
confirm initial focus, Tab wrap and Enter for Patch Bay, Reverb, About and idle
Auto-Sens. Enter from a closed Reverb combo closes the dialog; F4 opens the
combo, whose first Enter only commits/closes its popup. About's focused checkbox
also uses the default OK action on Enter. An original confirmation starts on OK;
Tab selects Cancel and Enter declines it. Numeric observations remain under
ignored build/wine-reference/dialog-keyboard-observations.json. No calibration,
initialization or device writes were tested against real Windows hardware.

Control pointer regions and context menus
-----------------------------------------
The decoded control maps assign double-click editing only to the sensitivity
value field (CValPreSens, 0x1400042b0); the ordinary knob/fader maps contain no
parameter-reset double-click handler. The existing HTML editor follows that
behavior. Wine GetWindowRect/MapWindowPoints observations place input 1's knob
in a separate 25x25 child (ID 775) and its value in a 37x13 edit (ID 782).
The observed preamp/header button children occupy 23x19 rectangles; nearby
captions are painted outside those children. These are Wine client coordinates,
not a comparison of native Windows font rendering or DPI scaling.

Original right-release handlers 0x1400035a0/0x140003510 reject MK_LBUTTON and
use PtInRect's inclusive left/top, exclusive right/bottom boundaries. The
button path additionally checks its availability callback before opening a
menu. tools/verify-control-hit.py executes 192 fixed rectangle/modifier cases
against these handlers and compares the HTML helper; 96 more cases exercise
the original unavailable-button gate. Window rectangles, availability and popup
dispatch are host stubs. Numeric vectors are in test/data/control-hit.json;
the measured child bounds remain in ignored build/wine-reference/pointer-control-bounds.log.
The left-release handler 0x1400032c0 releases capture and ends dragging regardless
of the remaining mouse buttons; 0x140002e30 also resets it on capture change.

Main-panel control geometry
---------------------------
The read-only tools/inspect-windows-layout.py verifies the running executable's
hash, records its DPI/client/menu dimensions and reads visible Win32 child
rectangles. Both views in the offline model report 96 DPI, a 978x410 client and
a 19-pixel native menu. The numeric fixture test/data/control-geometry.json
contains 128 Preamp and 174 Direct Mixer rectangles, translated by that menu
height into our complete-panel coordinates. Both views pass --compare.
Preamps repeat at 121 pixels; mixer channels repeat at 42 pixels, with 432 pixels
between input/playback groups. Dials measure 25x25, switch skins 23x19, faders
18x88. The return control, all four master faders and both 41x13 shared master
value windows are included.
The original mixer header reads VS PREAMP with an upward arrow.
The private observations remain under build/wine-reference/.
These measurements exclude native Windows font/DPI rendering and owner-painted
captions/backgrounds. They do not establish physical audio response or Windows
device communication.

Rotary display mapping 0x14001f0e0 / CCtrlWnd::Out2Pos (0x10000777e) rounds to
65 resource positions, rather than rotating continuously between indices.
Both resource constructors specify 65 frames. tools/verify-knob-display.py
executes 1,566 cases per original across every legal sensitivity, compressor,
pan and level index plus clamped boundaries; HTML uses the matching positions.
Resource endpoint getters are modeled; original bitmap painting is not executed.

Sensitivity UpdateText at 0x140023600 / 0x100014b48 selects 101 strings from
0x14029c970 / CSensTbl::m_str (0x10005d7e0). These use four columns: a leading
space below 10.0 and no dB suffix. Invalid stored indices select ???. Both
methods compare against current text before setting it. The HTML field uses
the original numeric spacing; slider accessibility text and tooltips retain dB.
tools/verify-sensitivity-display.py executes 1,648 full update cases per binary
with memory-only text/allocation hosts, including every input/index, unchanged
text and invalid indices. No native painting or device transport is executed.

The field's GetShow methods (0x14001a630 / 0x100014b08) require the preamp view
and an available channel: 1-4 at rate index 3, otherwise 1-8. The flag at device
offset 0xc38 / 0x864 is the host's preamp/mixer view flag, not connection state:
the two header-button SetToDev methods set/clear it. Eighty selector cases per
binary verify that visibility rule. Original offline model fields 0x10/0xa2c
select the rate index/view; these offsets are not USB protocol addresses.
Setting both fields exposes the preamp at 192 kHz without changing hardware.
The original shows a fixed 483x353 mask at complete-panel position 490,49 for
inputs 5-8, retaining static captions and replacing live controls/readouts.
Private captures and visible/hidden child observations are preamp-rate-1/3
under build/wine-reference/. The original rate and view were restored.
HTML retains the strip/caption brightness and uses fixed minimum-position
knobs/faders, blank values and grid-only compressor plots for unavailable
channels. Meter activity is hidden; captured drags and text edits are cancelled
when their channel becomes unavailable. Synthetic Playwright rate transitions
verify these states and restore cached values without device writes. Our own
control artwork and native font/bitmap painting still differ from the original.
The preamp background resources use a dark upper field (approximately #272727
away from the upper-left highlight) and a uniform #525252 parameter field.
HTML recreates these areas with panel-wide CSS gradients; it no longer repeats
the same highlight independently in every strip. The highlight is approximate.
The mixer background likewise has a shared upper-left highlight and separate
framed gray fader beds (approximately #484848), including both master groups.
The baked 192 kHz masks retain shaded neutral switch/knob faces; they do not
use the flat gray face of the ordinary disabled switch resource. HTML recreates
these distinctions with CSS. Needle length, caption weight and lighting are
authored approximations; the original bitmap assets are not distributed.

The shared master readout getter 0x140019900 reads a source-specific selected
side from state offsets 0x144c/0x1450. Callback 0x14001f040 selects that side;
0x140017f10 invokes it on changed or forced master refreshes. Left release
forces refresh even when a thumb click leaves the coefficient unchanged.
The macOS CBtnMstVol::OnUpdate (0x100023844) and CValMstVol::GetFromDev
(0x10002402c) use equivalent separate selectors at 0x1088/0x108c.
tools/verify-master-display.py executes both selectors/getters and the Windows
refresh path across 32 fixed traces per reference, including all four mixers,
unequal left/right values, silent/maximum levels and unchanged polls. The web
display matches. Visibility/painting and macOS notification scheduling are
modeled; these checks do not exercise original device transport. Wine/X11
observations with unequal in-memory model values additionally show the shared
readout changing to the clicked thumb's unchanged value on release.

Output-jack status selector 0x14001a860 and macOS CDispDMixOut::GetStat
(0x10001bb4e) select three artwork states per output pair: assigned to the
selected mixer, assigned elsewhere, or unavailable. At 192 kHz, pairs above
3/4 are unavailable and the effective mixer is A even when cached selection
contains B-D. tools/verify-output-jacks.py executes 720 fixed cases per original,
covering four rates, four mixers, five pairs and all nine routes; HTML states
match both. Painting/notifications/transport are not executed by this check.
Wine's offline model additionally shows green assigned text, light-gray other
routes and dark-gray unavailable pairs. The HTML panel uses its own CSS/text
with these state colors and a blue multiple-mixer active lamp. Native font and
bitmap rendering remain outside parity claims.

Switch palettes
---------------
Windows panel-resource constructor 0x1400129f0 loads resources 290/291/294 as
amber/blue/red clips. The equivalent macOS CRsPnl::Create (0x10002b286) names
BTN_AMBER, BTN_BLUE and BTN_RED. The Windows red clip begins at resource-object
offset 0x270; the macOS offset is 0xc0. Preamp creation 0x140010af0 /
0x10001a63c uses red for phantom, Hi-Z, phase and low-cut and amber for bypass.
Compressor and mixer stereo links, mixer mute/solo, master links and reverb use
red as well. Auto-Sens uses red; Multiple Direct Mixer uses blue. This corrects
the earlier generic yellow HTML switch palette and the separate phantom hue.
The three Windows clips and named macOS resources are byte-identical. Their
active face-center RGB values are amber (255,149,70), blue (101,196,255) and
pink/red (255,165,181). The HTML panel uses its own CSS gradients with these
colors, without shipping reference bitmaps. This is resource/constructor
evidence; complete bitmap painting and native font parity remain open.

Windows GetClip 0x140018df0 and macOS CBtnBmp::GetClip 0x100001be8 select
disabled-column * 4 + active-row * 2 + pressed. The shared 46x76 resources
contain two columns of four 23x19 clips. Disabled face centers are gray
(138,138,138) in every row; pressing changes the enabled bevel. macOS OnDraw
0x1000012c0 suppresses its mouse-down query when unavailable. Windows Begin/End
0x140018940/0x140016b30 change the availability column and host enabled state.
tools/verify-switch-frames.py compares all eight selectors on both originals
and four Windows transitions, with repaint/enabling host calls stubbed. Numeric
fixtures contain no manufacturer artwork. HTML uses its own CSS gray/pressed
faces and pointer capture; exact bitmap painting and native input tracking are
outside this selector comparison.

Windows driver compatibility checks
-----------------------------------
The vendor INF registers RDWM1110.SYS with ServiceType=1
(SERVICE_KERNEL_DRIVER). Its import table requires ntoskrnl.exe, USBD.SYS,
and portcls.sys, including PcInitializeAdapterDriver, PcNewPort, and
PcRegisterSubdevice. No portcls implementation was found in the installed
Wine 10.0 library directories. This is a concrete blocker to loading the
original Roland driver in the current Wine environment; an installer
completing would not demonstrate a working driver.

RDDP1110.EXE imports CreateFileW and DeviceIoControl. Its discovery paths and
enough of its control interface for the offline display model are traced;
full device-dependent interaction remains incomplete. A working Linux
ALSA driver would not automatically provide the Windows driver interface
expected by the vendor GUI. A dedicated compatibility bridge could be
investigated separately if running the original GUI becomes a goal.

Wine does include USB support; do not generalize these findings into a
claim that Wine cannot access USB devices or run any driver-related code.
Reference for the tested Wine version:
https://github.com/wine-mirror/wine/blob/wine-10.0/dlls/wineusb.sys/wineusb.c
