OCTA-CAPTURE USB/MIDI protocol
=============================

Device: Roland UA-1010, USB VID:PID 0582:0120.
Reference binaries: Windows 1.5.3 and macOS 1.5.9, identified in
drivers-manifest.json. Addresses below refer to the macOS x86_64 slices.
Status: static analysis unless explicitly marked as a hardware observation.
Preamp/compressor writes listed below have passed hardware readback tests.

USB interfaces (observed from the connected device descriptors)
--------------------------------------------------------------
All five interfaces are vendor-specific; bcdDevice=0200. The device is
connected at 480 Mbit/s through USB/IP in the development environment.

  Interface  Endpoint(s)       Transfer type / purpose
  0          05 OUT           asynchronous isochronous audio output
  1          85 IN            isochronous input with implicit feedback usage
  2          06 OUT / 86 IN   MIDI; bulk at alternate 0, interrupt at alternate 1
  3          82 IN            interrupt, 8-byte maximum packet at alternate 1
  4          81 IN            interrupt, 8-byte maximum packet at alternate 1

Interface 3 is the reference driver's status polling interface: CuDevPoll::Open
selects alternate 1 and reads its interrupt pipe. Eight-byte packets are
hardware-verified, with the rate in little-endian bytes 3..5 and alternating
packet byte 0 (00/01). Other status fields still need mapping. Interface 4's
meaning is not yet established.
Audio alternate settings 1,2,3,4 advertise 44100,48000,96000,192000 Hz.
Descriptors advertise 10 output/12 input channels at the first three rates
and four channels in each direction at 192000 Hz. This matches the record/
playback specification in the English v1.6 owner's manual, p. 95:
https://static.roland.com/assets/media/pdf/OCTA-CAPTURE_v1.6_OM.pdf
Signal/channel mapping still needs hardware verification.
The existing snd-usb-audio quirk only exposes 44100 Hz, S32_LE, 10 output
and 12 input channels. MIDI currently exposes one ALSA raw-MIDI subdevice.

Control transport
-----------------
The macOS GUI establishes CoreMIDI connections to OCTA-CAPTURE endpoints
named CTRL, separate from the regular musical MIDI endpoint. It sends
Roland SysEx through that connection. This is established by
CCplMidiClient::EstablishConnection at 0x100003f46 and CCplDeviceIO methods.

The macOS MIDI driver uses USB MIDI framing with cable numbers. Its input
and output cable mapping tables are identity maps 0..15. createDev at
0xd528 creates MIDI first and CTRL second; SetTxEps at 0xc336 and SetRxEps
at 0xd8cc apply those identity maps. This establishes cable 0 for MIDI and
cable 1 for CTRL in the reference implementation. The existing Linux
quirk's cable mask 0x0001 exposes cable 0 only; cable 1 is missing.
Cable 1 is hardware-verified: the standalone module exposes ALSA subdevice 1
as Control, and the bulk request returns a valid 1146-byte state payload.

USB clock requests
------------------
CuUsbDev::DevReqCall2 at 0x1732c issues vendor control transfers with
wIndex=0. Fsc_GetStatChk1 at 0x174bc uses:

  bmRequestType=c0 (device-to-host, vendor, device)
  bRequest=03, wValue=0001, wIndex=0000, wLength=0004

Bytes 0..2 hold the sample rate in little-endian order; byte 3 holds flags.
The reference interprets flag bits 0 and 1 as clear/set conditions; the
precise user-facing meaning of these conditions still needs verification.

Verified response at the device's current 48 kHz setting:
  response: 80 bb 00 00
  decoded: 48000 Hz, flags=00
Implemented in src/Usb.cpp (octa-probe), without claiming interfaces or
changing settings. Repeated reads at 48 kHz work after USB/IP reconnection.

Fsc_GetStatChk2 at 0x1757e reads c0/03/0002/0000, length 1, and compares
the result with 01. The hardware returned 01. Fsc_GetDIN at 0x17606 reads
c0/05/0000/0000, length 1; that query timed out in the initial test.

SendFsC at 0x177c8 negotiates a rate with:
  bmRequestType=40, bRequest=03, wValue=0008, wIndex=0000, wLength=0004
  payload: 01 rate_low rate_middle rate_high
It then polls Fsc_GetStatChk1, checking flags and the requested rate.
On the tested device, this does not change the clock when the requested
rate differs. Fsc_SetFs at 0x1768e uses the same setup packet with:
  payload: 40 rate_low rate_middle rate_high
This changes the rate. Bit 0 remains set during transition (about 0.55 s
in the local test), then clears; the readiness query returns 01.
The standalone module uses 40 for rate changes, polls for the requested
rate and clear flags, then checks readiness before selecting audio alternate
settings. It rejects status flag bit 1 rather than overriding that condition.
ALSA stream preparation and independent USB readback have passed at all four
supported rates under WSL. This does not establish working audio streaming.

SysEx envelope
--------------
Byte positions (hexadecimal byte values, zero-based offsets):

  0       F0                 SysEx start
  1       41                 Roland manufacturer ID
  2       10                 device ID used by this GUI
  3..5    00 00 4D           model ID
  6       11 or 12           data request (RQ1) or data set (DT1)
  7..10   aa bb cc dd         four 7-bit address bytes
  11..N   payload            7-bit data; RQ1 uses four size bytes
  N+1     checksum
  N+2     F7                 SysEx end

Checksum = (-sum(address bytes + payload bytes)) modulo 128.
Header bytes through offset 6 and the terminating F7 are excluded.
All address, payload, and checksum bytes are MIDI data bytes (0..127).
The four address/size bytes represent base-128 digits, most significant first.

Bulk state request
------------------
CCplDeviceIO::RqBlk at 0x10000a302 requests address 01 00 00 00 and size
00 00 08 7A (=1146 payload bytes). The complete request is:

  F0 41 10 00 00 4D 11 01 00 00 00 00 00 08 7A 7D F7

CCplDev::SetBlk at 0x100009434 validates a DT1 response with 1146 payload
bytes, checksum at offset 0x485, and F7 at offset 0x486 (1159 total bytes).
Its decoder includes four direct-mixer buses, eight preamp/compressor
channels, reverb, and output routing. The implemented layout is below.

Preamp/compressor bulk layout
----------------------------
Offsets are relative to the payload, excluding the 11-byte SysEx header.
Boolean channel flags use four low bits per byte: channel ch uses
payload[offset + ch/4], bit ch%4. Numeric columns hold eight channel bytes.

  Offset  Field
  15      phantom flags
  17      low-cut flags
  19      phase/polarity flags
  1B      Hi-Z flags
  1D      sensitivity indices
  25      stereo-link flags; bit pair, for pairs 0..3
  26      compressor enable flags
  28      gate indices
  30      attack indices
  38      release indices
  40      threshold indices
  48      ratio indices
  50      gain indices

Reference decoders: CCplDevPreAmp::SetBlk at 0x100009910,
CCplDevPreCmp::SetBlk at 0x1000097ee, and CCplDevPre2::SetBlk at
0x100009724. SetEach1 at 0x10000a8e0 establishes the same field mapping
for individual notifications. Independent implementation: src/Preamp.cpp.

Preamp/compressor individual updates
------------------------------------
Address: 00 05 ch parameter; ch is zero-based 0..7. Single data byte.
The original transmitter masks the channel to four bits; the receiver
checks that it is below eight for per-channel controls.

  Parameter  Meaning                 Reference transmitter
  00         phantom power           0x1000132a8
  01         low-cut                  0x100013d52
  02         phase/polarity           0x10001375e
  03         Hi-Z                     0x10001389c
  04         sensitivity              0x100014844
  05         preamp stereo link       0x100011a46
  06         compressor enable        0x1000152be
  07         gate threshold           0x1000160fc
  08         attack                   0x1000167a6
  09         release                  0x1000169dc
  0A         compressor threshold     0x10001633a
  0B         ratio                    0x100016570
  0C         compressor gain          0x100016c1a

For example, sensitivity channel 0, encoded value 0x14:
  F0 41 10 00 00 4D 12 00 05 00 04 14 63 F7
This is an encoding example, not a hardware-verified gain change.

Some display values are table indices rather than their numerical units.
Recovered GUI tables contain 101 sensitivity entries (0.0..50.0), nine
compressor ratios, 26 attack entries, and 46 release entries. Knob position,
display value, encoded state, and physical gain must remain distinct until
their conversion functions have been checked.

Write bounds recovered from the reference GUI ranges/tables:
  Boolean switches: 0..1; sensitivity: 0..100; gate/threshold: 0..50;
  attack: 0..25; release: 0..45; ratio: 0..8; compressor gain: 0..74.
src/Control.cpp rejects invalid channels, parameters, and out-of-range
values before MIDI access. Incoming state retains raw 7-bit indices.
octa-control writes one DT1 and immediately requests bulk state on the same
open CTRL connection; success requires the requested value in that reply.
tools/check-preamps.py additionally checks channel isolation and restores
each original value. Power and stereo coupling controls are excluded from
its automatic mutations.

Hardware-verified through WSL/USB-IP: low-cut, phase, sensitivity,
compressor enable, gate, attack, release, threshold, ratio, and gain on all
eight channels. Each was changed by one index, independently read back,
and restored; other preamp channels were checked for unexpected changes.
The complete 1146-byte bulk payload matched the initial state afterward.
This verifies these controls, not audio streaming or physical DSP response.

Direct mixer bulk layout and updates
-----------------------------------
Payload offsets are hexadecimal. There are four buses, ten channels per
source group, and five stereo pairs per bus. Packed flags use four low
bits per byte. The playback group adds 1F4 to the input offsets below.

  Offset  Input field                    Bus stride / channel stride
  058     stereo links                   2 bytes / packed pair flags
  060     mono switches                  2 bytes / packed pair flags
  068     solo switches                  3 bytes / packed channel flags
  074     mute switches                  3 bytes / packed channel flags
  080     pan                            40 bytes / 4 nibbles
  120     volume                         60 bytes / 6 nibbles
  210     reverb sends, input bus A only  6 nibbles per channel

Pan and volume are unsigned big-endian nibble coefficients, not MIDI
base-128 digits. Incoming raw values are preserved. Reference decoders:
CSysExBulk::GetPan at 0x100009e8e and GetVol at 0x100009f12.

Individual channel address:
  00 (06+source_group) ((bus<<4)|channel) parameter
source_group=0 input, 1 playback; bus=0..3; channel=0..9.
Parameters: 00 stereo link, 01 mono, 02 solo, 03 mute (one boolean byte),
04 pan (four nibbles), 08 volume (six nibbles). Stereo link/mono address
the pair using its first channel. CSysEx4::SetPan at 0x100020940 and
CSysEx6::SetVol at 0x100021e72 establish the group/bus ordering.
Reverb send uses 00 06 channel 0E with six nibbles, input bus A only.

Write bounds: pan 0000..8000, volume/send/return 000000..7FFFFF,
booleans 0..1. Hardware probes on a linked input pair show that mute,
solo, volume and reverb send also update the peer; pan remains independent.
A linked input master volume write also updates its opposite channel.
Individual notifications describe the addressed field; use the subsequent
bulk reply to observe coupled device changes. The reference fader's CVrTbl::m_vr at 0x10005c7d0 has
1025 monotonic coefficients from 0 to 7FFFFF; 200000 is unity. The
CCtrlLevelBase::SetRange at 0x10002151a uses control positions 0..1024.
This implementation uses raw coefficients rather than copying that table.

Master bulk fields:
  404..407 input master stereo links, one byte per bus, bit 0
  408..437 input master L/R volumes, six nibbles per channel
  438..43D reverb return, six nibbles
  43E..441 input/output master links, one byte per bus, bit 0
  442..445 additional master flags, semantics still unresolved
  446..449 playback master stereo links, one byte per bus, bit 0
  44A..479 playback master L/R volumes, six nibbles per channel
Master volume address: 00 group ((bus<<4)|LR) 01; group=08 input,
09 playback; LR=0 left, 1 right. Stereo link uses parameter 00 and LR=0.
Input/output master link: 00 08 (bus<<4) 0D, one boolean byte.
Reverb return: 00 08 00 07, six nibbles.
Reference: CCplDevDMix::SetBlk at 0x1000095d4 and
CCplDevDMixMaster2::Set at 0x100009a28.

Reverb, routing and persistence
------------------------------
Bulk payload: output routes at 05..09; reverb type at 0A; five pre-delay
indices at 0B..0F; five time indices at 10..14 (including the off slot).
Routing address: 00 03 00 pair, pair=0..4, one selection byte.
CCplDeviceIO::TxRevType at 0x1000271ca writes one byte to 00 04 00 00.
TxRevPreDly at 0x1000273fa uses 00 04 type 01; TxRevTime at
0x1000274dc uses 00 04 type 02. Both send one table-index byte. CDlgReverb::InitDlgItems at 0x1000278fc
sets pre-delay indices 0..12 and time indices 0..49. The Base.lproj
Reverb.nib menu order is OFF, ECHO, ROOM, SMALL HALL, LARGE HALL (0..4).
Pre-delay/time writes target active type banks 1..4; incoming bulk state
also retains the off bank. Patchbay.nib lists nine routing selections:
Direct Mix A..D (0..3), WAVE OUT pairs 1-2 through 9-10 (4..8).
The DSP bulk decoder is in src/Dsp.cpp; octa-state exposes these fields.
src/DspUpdate.cpp applies individual notifications for the mapped channels,
masters, effects and routes. Unknown selectors and malformed values leave
state unchanged. Stereo-pair notifications accept either channel of the
pair; the transmitter uses its first channel. Only input bus A sends and
the global reverb return are represented. Unmapped master flags are rejected.
src/DspControl.cpp validates typed writes against these bounds, uses
canonical selectors, and encodes the DT1. octa-dsp supports dry runs;
the MIDI backend verifies each write against a fresh decoded bulk reply.
Readback from the connected device and synthetic boundary tests validate
the layout. Under WSL, 361 scalar DSP changes passed write/readback and
restoration checks: mute, solo, pan and volume on all four buses and both
source groups; master volumes; reverb sends, return, type and all active
parameter banks; all five output routes. Expected stereo coupling was
checked. The complete raw payload matched the snapshot after every
restoration. Link/mono controls and physical DSP response remain unverified.

TxSaveLoad at 0x10002a946 writes one command byte to 00 00 00 01.
The confirmed callers at 0x10002a328 (Store Memory) and 0x10002a2ea
(Load Memory) send 00 and 01 respectively, after a confirmation dialog.
These persistent device operations are not exposed or hardware-tested yet.
No initialization, save, or restore operation has been executed. Disk .octa
presets use a separate Ver100 format; see preset-format.txt for its layout
and codec. Current-state export is read-only; no live preset restore is
implemented yet.

Input level meters
------------------
CCplDeviceIO::TxMtrSwitch at 0x10000b2b6 sends DT1 to 00 0A 00 00,
one byte: 01 enable, 00 disable. CUiDev::HandleLongData at 0x10000890a
recognizes level packets at 00 0A 00 01: eight consecutive 14-bit values,
two MIDI bytes per input, most significant seven bits first (16 payload
bytes, distinct from DSP nibble coefficients).
CDevLvMtrMgr::ChkMeter at 0x100025062 displays 20*log10(level/16383);
zero uses a -96 dB sentinel. These are reference display units; analog
calibration and channel identity still need signal-based verification.
The bounded decoder, switch encoder and conversion are in src/Meters.cpp.
Hardware verification received 39 complete, checksum-valid 29-byte packets
in two seconds while duplex audio ran. All eight levels were zero. The
captured silent frame is a regression fixture; nonzero channel identity
and calibrated levels still need signal-based tests. Meter output was
explicitly disabled afterward.
The octa-meters observer uses one exclusive CTRL connection, validates each
complete packet, and attempts disable on completion, callback cancellation
and errors. Normal completion, SIGINT, SIGTERM, a closed stdout pipe and
rejection of a competing observer were hardware-checked; passive reads
confirmed no remaining level stream and the bulk state was unchanged.
Offline transport tests cover partial transfers, malformed packets, read/
write failures and deadlines. Unplugging or forced termination can prevent
cleanup.
MidiSession keeps one CTRL connection and a bounded persistent receive
buffer for meter traffic, bulk queries and typed writes with readback.
It dispatches intervening notifications through the query listener, drains
already queued messages before transmitting, and excludes completion of
an older partial bulk frame from the new query. Queries are serialized;
reentrant calls return EBUSY. After an unresolved query, reopen the session
before querying again: the protocol has no transaction IDs for correlating
a late reply. Explicit meter disable remains available after query errors;
destruction attempts cleanup as a fallback and reports failures to stderr.
In-flight meter packets can still arrive after the disable command. The
shared-session checker validates these and requires 200 ms of quiet within
a three-second settling deadline before reporting successful shutdown.
The shared connection was hardware-verified with eight bulk queries,
including four writes of the current pan value, while meters remained
active. It also passed alongside timed 48 kHz duplex streaming (12 capture,
10 playback channels), with the complete bulk state unchanged afterward.
Native Debian validation remains required.

Auto-Sens messages (static analysis only)
---------------------------------------
TxASensStart at 0x1000288f8 sends 00 02 01 04 with a nonzero eight-input
selection mask as two nibbles, low nibble first. Its two-byte notification
uses four channel flags in each byte (CCplDev::SetEach2 at 0x10000a372).
TxASensStop at 0x10002888a sends one byte to 00 02 01 05: 00 finishes,
01 cancels (CDlgASens::Stop/Cancel callers). A completion notification at
00 02 01 05 clears all eight activity flags regardless of its data byte
(CCplDev::SetEach1 at 0x10000a8e0). Activity is not part of the bulk bank.
src/AutoSense.cpp implements these bounded codecs and atomic activity
updates. Offline fixtures check the wire bytes, all 255 nonempty channel
masks, reserved flag bits, repeated updates and rejection without mutation.
No automatic gain operation has been run or exposed through live I/O yet.

Audio packing and initial hardware tests
---------------------------------------
The macOS CPortProps::BytesPerUsbFrame at 0x13856 multiplies sample counts
by channel count and three bytes per sample. This agrees with the device's
three-byte/24-bit format descriptors. The stock Linux fixed quirk advertises
S32_LE instead; the standalone module uses descriptor-based S24_3LE.
Correct packing and successful preparation do not establish valid streaming.

Initial tests on the existing unmodified WSL driver:
  arecord -q -D hw:0,0 -f S32_LE -c 12 -r 44100 -d 1 -t raw /dev/null
  aplay -q -D hw:0,0 -f S32_LE -c 10 -r 44100 -d 1 -t raw /dev/zero
Both terminated with Input/output error. The capture was discarded; playback
contained only zero samples. USB/IP completion messages were present in the
kernel log. No native-Debian streaming result is available yet.

With the standalone module, octa-audio-check distinguishes preparation from
streaming and verifies wall time. At 48 kHz under WSL, eight-packet input
URBs complete about every 8 ms; packet lengths are normally 216 bytes
(six 12-channel frames). The aggregate input rate is approximately 6000
frames/s rather than 48000, and both capture and playback fail the timed
check before the host workaround. An independent asynchronous libusb
capture, with the ALSA module unloaded, reproduces the same 1/8 rate.

The tested usbipd-win revision aa3db8b omits VBoxUSB GET_DEVICE. VirtualBox
7.2.2 initializes its cached high-speed flag only in that request and uses
it for isochronous frame scheduling. The targeted Windows metadata query
in tools/initialize-usbipd-high-speed.ps1 restored correct timing: capture
and playback at all four supported rates passed octa-audio-check with no
ALSA errors and approximately 1002..1005 ms per second of frames. The
Windows driver version is 7.2.2.170484. This is a transport timing result;
signal integrity, channel identity and long-duration stability remain open.
A simultaneous 30-second 48 kHz test (12-channel capture discarded,
10-channel zero playback, S24_3LE) completed in 30.04 s with both tools
returning zero and no underrun/overrun messages. This is a short smoke
test, not long-duration or signal-quality verification.
See kernel/README.md for the repeatable host workaround.

Evidence and remaining verification
----------------------------------
Named macOS GUI methods were decompiled in Ghidra 12.1.2; selected original
decompilations and binary resources are ignored under doc/local/.
tools/ghidra/ExportSelectedFunctions.java exports selected functions from
a Ghidra project using an address<TAB>label input file.

Next requirements: reconcile bulk fields with the original GUI state; map all parameter bounds,
sample-rate/clock behavior, messages, and file formats; verify independent
encoders/decoders against original frames and real device responses.

The initial independent C++ encoder/decoder is in src/Protocol.cpp. Its tests
check the reference bulk-request and sensitivity frames, malformed frames,
7-bit constraints, request-size limits, and a synthetic 1146-byte bulk
roundtrip. The synthetic case is not a captured device response.
