OCTA-CAPTURE .octa presets (Ver100)
==================================

Evidence
--------
Windows 1.5.3 RDDP1110.EXE: Save at 0x140007720, SaveCpl at
0x140007820, byte writer at 0x14000a5c0, DWORD writer at 0x14000a630.
macOS 1.5.9 x86_64: CCplFile::Save at 0x10003a4b4, SaveCpl at
0x10003a66e, writeTextA at 0x10003a608, writeDWord at 0x10003c74a.
Both implementations use the following layout. This disk format is
separate from the device's Store/Load Memory commands.

All DWORDs are unsigned 32-bit little-endian values. Flags occupy one byte.
Nonzero flags load as true; writers emit 0 or 1. There is no checksum.

Offset  Size  Contents
0       32    NUL-terminated ASCII "OCTA-CAPTURE Control Panel Data"
32      7     NUL-terminated ASCII "Ver100"
39      20    Five output route DWORDs
59      44    Reverb type, then five interleaved pre-delay/time DWORD pairs
103     268   Four preamp pairs, 67 bytes each
371     1268  Four direct mixers, 317 bytes each
Total: 1639 bytes.

Preamp pair: link flag, then two channels. Each channel contains compressor
on/off, six DWORD indices (gate, attack, release, threshold, ratio, gain),
four flags (phantom, phase, Hi-Z, low-cut), and sensitivity as a DWORD.

Mixer: input/output link flag, five input pairs, five playback pairs,
input master, playback master. Each pair contains its link flag and two
channels. A channel contains mute, solo, send DWORD, pan DWORD, volume DWORD.
Each master contains link, return DWORD, left volume DWORD, right volume
DWORD. Playback send/return slots are written as zero by the reference;
the codec retains their file values. Mono switches, clock settings and
transient Auto-Sens/meter activity are absent from this format.

Implementation and verification
-------------------------------
Preset.hpp/Preset.cpp retain every file DWORD at full width, including
inactive slots. The decoder requires the exact size and version, rejects
trailing data, and normalizes flags on re-encoding. Decoding does not
validate device control bounds. Offline import preparation validates effective control bounds before
returning a target bulk message. Live application and raw recovery also
validate bounds before writing and require exact complete bulk readback.

octa-preset inspect FILE prints a summary. octa-preset normalize FILE writes
a canonical binary file to stdout. Neither command opens a device. octa-preset export [hw:CTRL-port] queries
the current bulk state and writes its Ver100 file to stdout. PresetState.cpp
validates the bulk reply before conversion. Incoming raw indices and
coefficients remain intact; exporting does not apply GUI write limits.
Only mixer A input sends and return come from the bulk payload. B-D sends
remain zero; B-D input returns retain the original constructor's unity
value, 0x200000. The Windows master constructor at 0x140006620 confirms
the same default. Playback send/return slots are zero.

The two test/data/preset-ver100-windows-*.octa fixtures contain synthetic parameter data. They
were produced by offline emulation of the original Windows SaveCpl, with
CFile::Write replaced by a memory sink: a zeroed state and state byte i set
to (37*i+11) modulo 256. No device state is used. Each executes 592 scalar
writes (256 flags and 336 DWORDs). Both round-trip byte-for-byte through our
codec; independent offset fixtures also check field meanings and ordering.

To regenerate, import the original RDDP1110.EXE into a Ghidra project and run:
  ghidra.analyzeHeadless PROJECT_DIR PROJECT -process RDDP1110.EXE \
    -noanalysis -readOnly -scriptPath tools/ghidra \
    -postScript EmulatePresetWriter.java OUTPUT_DIR
The script checks the exact executable SHA-256 before emulating it. Driver
archive provenance is in drivers-manifest.json. Manufacturer binaries and
decompilation output remain excluded from Git. These tests establish
serialization compatibility; they do not establish live restore behavior.

Bulk export reference
---------------------
test/data/preset-export-bulk.syx is a synthetic DT1 whose payload byte i is
(7*i+3) modulo 16. preset-export-reference.octa is the output of the original
Mac CCplDev constructor (0x100008afc), SetBlk (0x100009434) and SaveCpl
(0x10003a66e), executed in Unicorn with Objective-C file calls replaced by
a memory sink. The converter must produce the exact same bytes. A captured
hardware bulk reply was also compared with this reference path, and export
left the complete bulk state unchanged.

Optional reference regeneration requires Debian's python3-unicorn package:
  python3 tools/emulate-bulk-preset.py gui-x86_64 BULK.syx OUTPUT.octa
The tool verifies the exact executable hash and the bulk checksum. It loads
only the specified original binary into emulated memory and bounds execution
by instruction count and time. It performs no device I/O. Manufacturer
binaries and hardware snapshots remain local; the committed fixtures contain
synthetic parameters only. Live application is checked separately below.

Offline import preparation
--------------------------
PresetImport.cpp implements preset_to_bulk(preset, current_bulk). It returns
one complete DT1 target without opening a device; a failure returns no
partial target. octa-preset prepare FILE CURRENT.syx writes the encoded frame
to stdout. CURRENT.syx must be a complete checksum-valid bulk reply.

All effective preamp, compressor, routing, mixer, master and reverb values
use the existing typed control validators before encoding. The inactive
reverb bank 0 permits raw seven-bit indices. Inactive file send/return slots
are ignored by the hardware mapping, including full-width values, as in
the reference. The input Preset retains those values for file handling.

The reference loads into a newly constructed CCplDev and copies routes,
reverb, preamps and mixers into its current object. Consequently, all mono
switches and the unmapped per-mixer flag (bulk 0x442..0x445) reset to zero.
Other reserved payload bits/bytes start at zero in TxBlk. Current cached
device properties in the first five payload bytes are retained with the
original flag canonicalization: bytes 0 and 3 keep bit 0; byte 4 is zero
when byte 2 equals 3. Current properties are separate from preset contents.

The synthetic preset-import-profile.octa exercises nonzero controls and
ignored full-width fields. GeneratePresetImport.py reproduces it. The
preset-import-reference.syx fixture was captured from original LoadCpl
(0x10003a980), Set (0x10003be72), and TxBlk (0x10002a9b0) in CPU emulation.
The reference harness supplies cached device properties from the current
bulk prefix and replaces file reads/MIDI output with memory streams.

To regenerate the reference using the existing synthetic current bulk:
  python3 test/GeneratePresetImport.py test/data/preset-import-profile.octa
  python3 tools/emulate-bulk-preset.py gui-x86_64 \
    test/data/preset-export-bulk.syx OUTPUT.syx \
    --import-preset test/data/preset-import-profile.octa
The complete prepared frame, including its checksum, matches this reference
byte-for-byte. A hardware-derived state/preset pair also matched offline.
These offline reference comparisons do not exercise hardware.

Live application and recovery
-----------------------------
octa-preset apply FILE NEW-RECOVERY.syx [hw:CTRL-port] reads the current
state, creates a new recovery file exclusively (0600, fsync before device
write), sends the prepared DT1 and queries the complete bulk state. An
existing recovery path is rejected without changing parameters. Exact
Message equality is required, including fields absent from .octa files.

On failure after a write attempt, or SIGINT/SIGTERM during application,
the command closes its connection and attempts verified raw recovery on
a fresh connection. octa-preset restore RECOVERY.syx [hw:CTRL-port] can
repeat that operation manually. Raw recovery preserves mono and opaque
fields that preset application resets according to the original driver.
Forced termination, power loss or disconnection can prevent recovery;
retain the recovery file and check the command's result. File fsync does
not guarantee directory-entry persistence across a system crash.

tools/check-preset-import.py is read-only by default. --write checks an
existing recovery-file collision, current-preset application, a one-unit
pan change and a one-unit compressor-attack change. Each case checks the
full target and restores the original raw state independently. These
checks pass on the attached WSL device with strict and release binaries.
SIGINT and SIGTERM after transmission also restored the full raw state
in a separate WSL hardware check. Native Debian remains unverified.
Device Store/Load Memory is separate and remains unimplemented.
