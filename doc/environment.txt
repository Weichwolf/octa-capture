OCTA-CAPTURE: native development environment
==========================================

Target
======
Debian 13 (trixie), x86_64, with direct USB. The development kernel is
6.12.113+deb13-amd64. Recheck the running kernel, module binding, device
permissions and tool versions before relying on build or runtime evidence.

Downloads
=========
Official Roland product page:
https://www.roland.com/global/support/by_product/octa-capture/updates_drivers/
Windows 10/11: 1.5.3, octa_w1011d_v153DL.zip (6,709,970 bytes).
macOS Sonoma 14 or later: 1.5.9, octa_mac14drv_m159.tgz (2,347,347 bytes).
Both archives were fully read and checked for archive errors.
Sources, timestamps, sizes, and SHA-256 hashes: drivers-manifest.json.
Verification from doc/: sha256sum -c SHA256SUMS
File lists: *.contents.txt; download pages: roland-*-download.html.
The archives contain proprietary binary drivers, not Linux source code.

Existing Linux support
======================
Linux already contains an entry for 0582:0120 with fixed 44.1-kHz audio
formats and MIDI; interfaces 3 and 4 are ignored in that entry.
Source reference:
https://github.com/torvalds/linux/blob/master/sound/usb/quirks-table.h
Device enumeration does not establish working recording or playback.
The standalone snd-octa-capture module uses a private ALSA source copy;
Debian's kernel and source tree remain untouched.

Development setup
=================
Build the module against matching Linux 6.12 sources and prepared headers,
including Module.symvers. tools/setup-native-dev.sh installs native tools,
device-specific access rules and the bounded development helper. It requires
build/driver-native/snd-octa-capture.ko for the running kernel and writes
/etc/octa-capture-dev.env. The GUI/backend runs as the regular user.
See ../kernel/README.md and ../README.md for build and installation commands.
Manufacturer analysis remains private under doc/local/; recovered protocol
facts and verification limits are recorded in usb-midi-protocol.txt.
